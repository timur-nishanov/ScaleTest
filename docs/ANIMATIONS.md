# Анимации — конвенции (GSAP)

## Принципы моушена (гайд YC, раздел 7.1)

Композиция собирается **последовательно, поэлементно** — «акцентированная сборка кадра», а не плавная трансформация. Три приёма:

1. **Появление** — детали появляются резким катом с лёгким инерционным движением (`cutIn`).
2. **Соединение** — элементы стыкуются через короткий соединительный «клик» (`clickIn`).
3. **Клонирование** — тиражирование элементов (появится на этапе моушена, где потребуется).

**Типографика**: текст появляется катами, **пословно** — каждое слово доезжает; можно с цветовым выделением акцентов в момент появления (`wordsIn`, GSAP SplitText).

Реализация — **упрощённая тач-версия** (решение заказчика 25.08: на киоске анимации не должны заставлять ждать): `src/animations/assemble.ts`, фабрика `assembleScreen(root)` — один быстрый групповой кат по `data-assemble`-элементам (autoAlpha + небольшой y-сдвиг, стаггер 0.05, вся сборка ~0.5 с). Пословная типографика (SplitText) и «клик»-стыковки из полного гайда на киоске не используются — при желании вернём точечно на этапе моушена. Переходы между экранами — жёсткий кат (уходящий экран без анимации) + сборка входящего. Применено на экранах 1–3.

Договорённость с командой Yandex Cloud (переписка артдир ↔ разработчик, 25.08):
анимации делаем **сразу на GSAP**, чтобы команда YC могла перенести их в свой код
без переписывания («мы перетащим к себе просто»).

## Правила

1. **Только GSAP** (v3.15, все плагины теперь бесплатны — Draggable, InertiaPlugin и т.д. в составе пакета `gsap`).
2. **Фабрики без React** — всё живёт в `src/animations/*`: на вход DOM-элементы и колбэки, на выход tween/timeline/Draggable. React-компоненты только вызывают фабрики в `useEffect` и убивают их в cleanup. Такой модуль переносится в любой стек как есть.
3. **GSAP пишет в DOM напрямую** — никаких setState на кадр. Колесо: React рендерит карточки один раз, углы каждый кадр ставит `gsap.set` (критично для 60fps на 4К).
4. Регистрация плагинов — один раз в модуле, который их использует (`gsap.registerPlugin(...)`).
5. Тайминги и изинги — параметры фабрик с дефолтами; тюним на целевом железе, не хардкодим по коду.
6. Пресс-стейт 0.94 — единственное исключение: чистый CSS `:active` (это стейт, а не анимация; аннотация макета «Скейл при нажатии 0.94x везде»).

## Что уже на GSAP

| Анимация | Файл | Механика |
|---|---|---|
| Интро колеса (прогон по всем карточкам и возврат) | `src/animations/wheelIntro.ts` | timeline из двух твинов прокси, ease power2.inOut; прерывается пальцем (killTweensOf в onPress) |
| Драг колеса с инерцией и снапом | `src/animations/wheelDrag.ts` | Draggable (type:'x', прокси-паттерн) + InertiaPlugin, snap к шагу 15°, edgeResistance, maxDuration 1.2 с |
| Шаг стрелками / программный снап | `src/animations/wheelDrag.ts` → `tweenWheelTo` | твин прокси, power3.out |
| Переходы экранов, появление попапа | `src/animations/transitions.ts` | заготовки фабрик (screenEnter, overlayEnter) — наполняются на этапе моушена |

Прокси-паттерн колеса: невидимый элемент, его `x` — единственный источник угла;
интро, драг и стрелки твинят один и тот же прокси, поэтому конфликтов состояний нет.
