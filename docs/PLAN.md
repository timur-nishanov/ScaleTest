# План внедрения — «Собери свой идеальный бандл»

Проект: интерактив Yandex Cloud для Yandex Scale 2026.
Дедлайн: **конференция 24 сентября 2026** (чем раньше — тем лучше).
Носитель: тач-экран 4K 55″ (3840×2160) + веб-версия для рассылки пользователям.

Истина по текстам и структуре — **макеты Figma** (файл Yandex-Scale-2026), ТЗ-док — вторично. Все найденные расхождения — в `DESIGN-NOTES.md`.

---

## 1. Архитектурные решения (приняты, чтобы минимизировать правки)

| Решение | Зачем |
|---|---|
| Вёрстка в дизайн-координатах 3840×2160 + `Stage` со scale-to-fit | Размеры из Figma переносятся 1:1 без пересчётов; на любом экране (превью у заказчика, веб-версия) картинка идентична киоску |
| Экраны — конечный автомат (zustand), без роутера | Киоск-флоу с автосбросом и оверлеями; веб-версия использует тот же автомат |
| Весь контент в `src/data/*`, тексты в `strings.ts` | Финальные тексты от YC приземляются правками данных, не кода |
| Все спорные механики — флаги в `config.ts` (таймер 45/60, порядок слотов, случайный выбор в ветке Б) | Ответы на открытые вопросы = правка одной константы |
| Ключи сервисов (`pg`, `kafka`, …) сквозные: данные ↔ имена файлов ассетов ↔ колонки аналитики | Заливка ассетов и выгрузка аналитики не требуют маппингов |
| Аналитика: контракт строки попытки по таблице ТЗ + подключаемый транспорт (localStorage-очередь → HTTP) | Бэкенд подключается позже без изменения игры |
| Механики (колесо, dnd, таймер, idle) отделены от визуала | Этап вёрстки красит готовое, а не переписывает |

Стек: Vite + React 19 + TypeScript, zustand (стейт), **GSAP** (все анимации — требование команды YC: они заберут анимации к себе, поэтому фабрики без React в `src/animations/*`, конвенции в `docs/ANIMATIONS.md`), без роутера и UI-библиотек. Колесо — GSAP Draggable + InertiaPlugin; dnd палитры на pointer events (тач + мышь едины).

## 2. Что уже сделано (этот PR)

- Скаффолд проекта, структура папок, конфиг, токены-плейсхолдеры.
- Рабочий сквозной флоу всех экранов в каркасном (wireframe) виде: заставка → режим → колесо задач → сборка/бандлы → попап результата, таймер 45 с с красной зоной, автосброс 30+15 с с попапом «Вы ещё здесь?», монетная логика.
- Колесо карточек: геометрия из макета (шаг 15°, центральная 790×1060), интро-прокрутка по всем карточкам, драг с инерцией и снапом, стрелки. Физику тюним на железе.
- Drag-and-drop палитры в слоты + тап-механика по ТЗ (тап = описание сервиса, не постановка).
- Контент: 10 задач сборки, 6 задач × 3 бандла, 13 сервисов палитры, 18 тегов заставки, все подписи (из макетов, где читаются; остальное из прототипа с пометкой `TODO(design-sync)`).
- Контракт аналитики по таблице ТЗ + офлайн-очередь.
- Документация: разбор макетов (`DESIGN-NOTES.md`), декомпозиция рефов (`REFS.md`), схема аналитики (`ANALYTICS.md`).

## 3. Этапы дальше

### Этап 1 — Ассеты и токены (частично закрыт, остаток блокируется заказчиком)
✅ Палитра, типографика (YS Display/Text), радиусы — сняты из макетов и уже в `tokens.css`.
✅ Тексты всех карточек, попапов, кнопок, палитры — сверены с макетами дословно, в `data/*`.
Осталось от заказчика: файлы шрифтов, логотип, иконки сервисов, иллюстрации (`public/assets/README.md` — куда и с какими именами).

### Этап 2 — Вёрстка экранов 1:1 по макетам (основной объём)
По команде заказчика. Порядок: заставка → выбор режима → колесо задач → экран сборки → экран бандлов → попапы результатов. Все стейты из Figma (ховер для веба, нажатие тач 0.94, красный таймер, drag-стейты слотов). Приёмка каждого экрана скриншот-сравнением с макетом.

**Статус (26.08, вечер): этап закрыт (PR #4–21).** Все 6 экранов и попапы 1:1 по макетам со всеми стейтами: заставка, выбор режима, колесо задач обеих веток (чип «Монета за конкурс» в Б, память позиции при «Назад», интро с мягким появлением), экран сборки (таймер с round-cap дугой, SVG-пунктир dash 16, драг без дублей с hug-плашкой сервиса), экран бандлов, попапы всех исходов (иллюстрации, баннеры монеты, нейтральные чипы в Б) с плавным появлением. Переходы экранов — фейд-кат; пресс-стейты 0.94 на всех больших карточках; предзагрузка всех ассетов; ассеты — полный комплект. Дальше по этапу — только правки по фидбеку коллег заказчика.

### Этап 3 — Моушен и полировка взаимодействий
Всё на GSAP по конвенциям `ANIMATIONS.md` (переносимо в код YC). Тайминги интро колеса, инерция/снап под палец на целевом железе, переходы экранов, появление попапов, «полёты» сервисов в слоты, бегущая строка тегов, пульс CTA. Ориентиры — рефы артдира (`REFS.md`); «вертелки» согласовываем с артдиром итерациями.

### Этап 4 — Бэкенд аналитики и админ-выгрузка
Минимальный приёмник событий (POST, батчи) + хранилище + **выгрузка Excel/CSV одной кнопкой или ссылкой** (по переписке в ТЗ: полноценная админка не нужна). Хостинг на нашей стороне, домен, HTTPS. Отдельно: страница-заглушка для веб-версии рассылки (если нужна другая точка входа — уточнить).

### Этап 5 — Киоск-режим и прогон на железе
Автозапуск браузера в kiosk-mode (готовим инструкцию/скрипт), wake lock, запрет системных жестов, прогон производительности на 4K (цель 60 fps: transform-анимации, contain, без тяжёлых теней/блюров на больших слоях), тест тача (мультитач-защита), длительный soak-тест с автосбросом.

### Этап 6 — Контент-фриз, QA, приёмка
Вычитка текстов YC, проверка правильных ответов архитекторами YC (наборы связок), финальный чек-лист по стейтам, передача ссылки и инструкции стендистам (монета/наклейка).

## 4. Ограничения и риски

- ~~Figma MCP лимит~~ — **снят**: работаем через копию файла с фулл-ситом (`uQ5AOTiVFp6NILcvOLIMly`), design context и метаданные доступны; тексты и токены уже синхронизированы.
- **Сеть окружения**: сами сайты-рефы недоступны (egress-политика, включая web.archive.org), но их механика подтверждена публичными разборами — GSAP/ScrollTrigger (lionsgoodnews), WebGL+GSAP+Lenis (ponpon-mania), см. `REFS.md`. На тайминги это не влияет — тюним по ощущению на железе.
- **Производительность 4K**: колесо и dnd уже на transform/rAF; бегущую строку и тени проверить на железе — это главный риск фпс.
- **Тач-браузер киоска**: нужно знать ОС/браузер киоска (Chrome kiosk? Яндекс Браузер?) — влияет на автозапуск и жесты. Вопрос заказчику.
- **Веб-версия для юзеров**: макетов под мобильные нет. Если нужна мобильная адаптация — отдельный этап (сейчас веб-версия = та же сцена с letterbox). Вопрос заказчику.
- **«Вы ещё здесь?»**: попапа нет в макетах — нужен дизайн или согласовать каркасный.
- Полный список расхождений ТЗ↔макеты с принятыми дефолтами — `DESIGN-NOTES.md`, раздел «Расхождения».
